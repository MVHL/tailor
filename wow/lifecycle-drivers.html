What Drives What

No stages. Each artifact is driven by the ones above it — an artifact is workable the moment its parents are canonical. The team's next step is always the frontier: the highest artifacts that are unblocked but not yet canonical. This is the artifact-primary reading of the same data as the stage-by-stage lifecycle — that view answers "where are we?" for stakeholders; this one answers "what can I do next?" for the squad. Companion to the playbook and ticket anatomy.

How to use it — the whole method in three steps:
  1. Mark what's canonical today (agreed, traced, source-of-truth — per the DoR checks).
  2. Find the frontier: every artifact whose parents are all canonical but which isn't yet. That set is the next step — no meeting needed to know it.
  3. Work the frontier in parallel. Anything below it is blocked; anything above it is done. Nobody waits on a stage.
Intake: a Signal is quoted, never rewritten; an Ask is the client's solution hypothesis — never copy it into Requirements. A Problem goes canonical only with an evidence: SIG#/ASK# link, so an Ask with no Problem is visible as untriaged intake, and a Problem with no Signal is visible as an invented need. The spike branch is optional — most problems skip straight from Problem to Requirements; run a spike only when the problem touches legacy or undocumented behavior. Ceremonies hang off transitions, not the other way round: Problem framed → hold triage; AC canonical + sprint pull → agent drafts both plans; plans finalized → code starts.
